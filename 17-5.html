JS 的两种定时器

setTimeout 到点执行一次，setInterval 每隔一段时间执行一次；两个都会返回一个 ID，交给 clearTimeout / clearInterval 就能取消。

三、顺带看看执行顺序 同步 → 微任务 → 宏任务

同步代码先跑；Promise 的 .then 是微任务，紧跟其后；setTimeout(fn, 0) 是宏任务，排在最后——哪怕写的是 0 毫秒。

    四、两者对比

    对比项 setTimeout setInterval
    执行次数 只执行 一次 一直重复，直到被清除
    返回值 数字 ID（浏览器里从 1 开始递增） 数字 ID
    停止方式 clearTimeout(id) clearInterval(id)
    时间含义 等多久之后执行 每两次执行之间隔多久
    典型用途 延迟提示、防抖、失败后重试、动画收尾 时钟、倒计时、轮播、进度轮询
    要注意 写 0 也不是立刻执行，是「尽快」排进任务队列 页面切到后台会被浏览器限速；回调里报错也不会自动停

    五、核心代码

    // 一次性：2 秒后执行，返回 ID 可以取消
var id = setTimeout(function () {
  console.log('时间到');
}, 2000);
clearTimeout(id);

// 周期性：每 1 秒执行一次
var clockId = setInterval(function () {
  clock.textContent = new Date().toLocaleTimeString('zh-CN', { hour12: false });
}, 1000);
clearInterval(clockId);
    • 定时器的计时并不精确：主线程忙时，回调只能排队等着，所以实际触发时间往往比设定值晚一点。
    • setInterval 的回调执行时间会比间隔长吗？会——如果一次回调耗时 1.2 秒，而间隔是 1 秒，队列里就会堆积，这时用「setTimeout 里再排一个 setTimeout」更稳。
    • 两个定时器都不阻止页面继续执行，它们是异步的：代码先往下走，时间到了才回来执行回调。
