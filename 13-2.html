线性图标：Lucide（SVG）

这里的每一个图标都是页面里真实的 <svg> 节点：24×24 的视口、描边用 currentColor、粗细由 stroke-width 控制。写完 <i data-lucide="star"> 后由本地脚本替换成 SVG。

24001010417 涂玮轩

⚠ 本地脚本 cdn/lucide/lucide.min.js 没有加载成功，图标无法渲染。请确认文件存在（见页面底部说明）——这正体现了 SVG 方案对 JS 的依赖。

原理：JS 把占位标签换成 SVG 图标本体是一段矢量路径

<!-- 你写的：一个占位标签 -->
<i data-lucide="star"></i>

<!-- 脚本跑完后，DOM 里变成这样 -->
<svg class="lucide lucide-star" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="2"
     stroke-linecap="round" stroke-linejoin="round">
  <path d="M11.5 2.3a.5.5 0 0 1 .95 0l2.3 4.7…"></path>
</svg>

页面底部加载 cdn/lucide/lucide.min.js（Lucide 1.59.0 UMD 版），再调用 lucide.createIcons() 完成替换。当前页共渲染出 — 个 SVG。

右键 → 检查，可以看到它们是 <svg><path>，不是字体字形。所以能用 CSS 单独控制描边宽度、线条端点和填充。

这是字体图标做不到的：字体只有固定字重，而 SVG 的描边是节点属性，可以被 CSS 覆盖成任意数值。

手写内联 SVG 不依赖任何脚本，最“纯”的用法

<svg viewBox="0 0 24 24" fill="none"
     stroke="currentColor" stroke-width="2"
     stroke-linecap="round" stroke-linejoin="round">
  <circle cx="12" cy="12" r="9"></circle>
  <circle cx="12" cy="12" r="4"></circle>
  <path d="M12 3v3M12 18v3M3 12h3M18 12h3"></path>
</svg>

自己写 path 的好处：完全可控、可离线、不需要 JS、也不增加额外请求。缺点是图形得自己画。

上面两个图形是纯静态写在 HTML 里的，即使脚本被禁用也照样显示。

和字体图标对比 13-1 页用的是 Font Awesome 字体方案

维度 Font Awesome（字体图标，见 13-1） Lucide（SVG，本页）
图标本体 字体文件里的一个字形，靠 --fa 编码映射 DOM 里的 <svg> + <path> 路径
引入方式 一个 CSS + 字体文件，纯静态 一个 JS 脚本，运行时替换成 SVG
依赖脚本 不依赖 依赖，脚本失败图标就不出现
上色 color color（currentColor）
描边粗细 不可调，只有固定字重 任意，stroke-width 实时生效
品牌图标 有（github / weixin / bilibili 等） 1.x 版本已移除，只做 UI 线性图标
本地体积 4 个字体子集约 0.3 MB 单个 UMD 脚本约 0.45 MB
单独取出 只能复制字符，拿不到图形 右键复制整个 SVG 就能带走

本页说明与局限 用 SVG 方案的注意点

  • 脚本已下载到本地 cdn/lucide/lucide.min.js（Lucide 1.59.0，ISC 许可），断网可用；页面底部先引脚本、再调用 lucide.createIcons()。
  • createIcons() 是「一次性」的：之后用 JS 动态插入的 <i data-lucide> 需要再调用一次，否则不会变成 SVG。
  • 图标名找不到时，替换函数会跳过并在控制台给出警告，页面上只剩空标签。
  • Lucide 1.x 不再包含品牌 Logo（github、twitter 等），这类需求仍需 Font Awesome 的 fa-brands。
  • 若只用到十几个图标，生产环境建议按需打包（或用 sprite 内联），不要整包引入 0.45 MB。
